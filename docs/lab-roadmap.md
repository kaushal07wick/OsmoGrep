# Workspace Lab delivery

All six features are opt-in. The existing CLI, session format, provider adapters, tool approvals and ordinary chat remain compatible. New records are versioned and project-scoped; no companion or device OS is downloaded at startup.

| Order | Feature | Delivery check |
| --- | --- | --- |
| 1 | Replayable bug reports | Selected-source capture, inspection, non-executing import/export, peer reference, bounded VM replay and cleanup |
| 2 | Compare two fixes | Same base and reproduction, independently saved outcomes, guarded application of a chosen snapshot |
| 3 | Team code contracts | Versioned agreement, explicit acceptance, source drift detection and targeted peer updates |
| 4 | Before/after app behavior | Reusable device flow, paired observations, image/trace differences and source references |
| 5 | Context inspector | Opt-in request evidence, provenance, corrections and stale source references without exposing credentials |
| 6 | App failure scenarios | Explicit bounded perturbations in isolated devices/VMs, restoration and replayable evidence |

Validation uses local fixtures first. Runtime exports distinguish observations from independent attestations. An unavailable VM/device service is a visible failure; it never selects host execution or a different device. Real VM/device validation is reported separately from mocks.
